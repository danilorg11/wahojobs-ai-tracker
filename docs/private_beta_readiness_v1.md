## Validation strategy and provisional objectives

Use existing pinned Python/Node/jsdom and guarded runner with disposable databases,
loopback-only transport and explicit blocked recovery port 8802. One test listener
owner at a time unless independently reserved ports are proven. Final selection is
defined in evidence before the final run. Native browser accessibility is checked
early; DOM/HTTP evidence is labelled separately if browser trust blocks access.

Provisional local objectives (not hosting SLAs): warm Matches p95 <= 2 s, cold
Matches <= 5 s, exact detail/My Jobs p95 <= 1 s, confirmation/correction p95 <= 2 s,
no unexpected 5xx or state loss in bounded sessions. Report sample size, actual
inventory, clock, hardware, concurrency, errors and quantile method before judgement.

## Material decisions and changes

Typed preferences now render and edit their existing authoritative values, including
pay minimums, workload, schedule and phone preference, with draft review and explicit
confirmation. Shared navigation/style spans entry, profile, Matches, detail and My Jobs.
Employer URLs reject credential/backslash ambiguity. Request IDs/closed diagnostics
have UTC time and optional bounded rotating local logs. Source maintenance gains
actionable coverage/age/held/repair summaries without provider or model execution.

Manual intake retains explicit personal skill-list items without professional-domain,
duration or proficiency inference; ambiguous negative, future and reported claims remain
unconfirmed/absent. The fresh support/generalist facts still yield no recommendations.
This is defensible under existing selection policy; normal Browse jobs permits inspection
and tracking without falsely endorsing fit. Google fixture catalog/company delegation
now matches the existing inner routes. The snapshot cohort does not establish useful
current beginner/language/support coverage; that is a real-source activation dependency.

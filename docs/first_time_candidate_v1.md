## Integrated behavior

Manual checkpoints use the existing private correction-draft sidecar, selected
only by the authenticated account/principal/environment binding. They contain no
profile identity or confirmation authority. Compare-and-swap rejects stale edits;
an exact retry is idempotent. Refresh and a new session restore saved material with
fresh review tokens. Confirmation still uses the existing artifact/create-once
path. Later correction uses normal revisions and preserves job/application history.

The shared editor exposes only the creation contract's supported fields. Linked
study records and per-item experience remain correction capabilities; creation
uses independent study fields and complete employment strings. No new taxonomy,
matching dimension or required qualification was added. Unknown proficiency and
credentials stay unknown until the candidate supplies them.

With extraction disabled, the account page offers manual creation and a clearly
labelled saved-review resume link; no unusable upload form is offered. With the
existing labelled offline adapter, tests exercise multipart upload, correction,
interruption/new-session resume with extraction disabled, confirmation and replay
without duplicate consumption. See [the existing intake contract](ai_profile_intake_foundation.md)
for future extraction configuration; this milestone enables no external adapter.

The development entry point `scripts/first_time_candidate_demo.py` extends the
existing controlled provider and durable product composition. It starts with zero
users and zero profiles, creates only an invitation using the account service,
and uses synthetic source fixtures with normal eligibility and matching. The
browser creates the account/profile through ordinary supported forms. Every page
labels the synthetic identity/extraction context. Runtime guards exclude 8802 and
non-disposable database access.

The managed browser cannot trust the disposable HTTPS certificate. No certificate
bypass, machine CA installation, cookie weakening or HTTP auth workaround is used.
The evidence distinguishes real DOM/script-to-HTTPS validation from browser layout
replays of captured HTML, and records this remaining full-browser limit.

# WahoJobs: one publication process

The owner authorized this replacement on 2026-10-28 for **all current and future
publications**. Use `scripts/publication.py`, `docs/publication.md` and
`deploy/publication/profiles.json`. These replace former blanket and routine-only
rules; they do not renew access, erase debit, accept unknown results or transfer
somebody else's custody.

## Prepare the actual change

- Use the same protocol for content, pages, UI/features, APIs/backend, data,
  integrations, accounts and infrastructure. Coordinated changes have executable
  domain steps and real dependencies, not a rejected class or a separate queue.
- Review the diff against the actually accepted version, not an assumed Git
  default. Classify unknown files/effects before mutation. A coupled transition
  belongs in one transactional domain step with a compatible exit.
- Finish code, affected tests, build, review and recovery/cleanup before opening
  private access or requesting the final production decision. Present exact
  sources/artifacts, resources, measured timings, limits and specific authority.
- Reuse tests/builds/reviews while source, dependencies, tools and configuration
  still match; reference original results and dates. Calendar age alone does not
  invalidate immutable evidence. Reobserve mutable production/ownership/readiness
  facts immediately before mutation. Preserve valid independent progress.
- Do not add exhaustive censuses, hourly/daily waits, database copies, social
  sign-ins, private SSH, dedicated observation periods or fresh namespaces without
  a named dependency/risk and exit criterion. Keep real source quotas and runtime
  startup costs; unrelated releases do not inherit them.

## Durable recovery and coordination

- Admit intent durably before dispatch. After timeout, interruption or lost
  output, resume the same operation and observe it. Never duplicate an uncertain
  action. Its reservation survives process exits and access expiry.
- Serialize overlapping actual resources and their parents (whole Vercel project,
  database or host). Independent work may prepare, qualify and publish while an
  unrelated operation needs attention. Do not use one queue's delay as a global
  hold unless its actual custodian owns such a hold.
- All publishers of a resource must use the same canonical coordinator. Prepare
  handoff with `scripts/publication_transition.py`; require actual closure and
  adoption/inactivity evidence before activation. Until then respect legacy
  global holds and the bridge. A new local lock cannot fence an old publisher.
- Keep native maintenance/lifetime gates, transactions and source/identity
  authority. Stop on a foreign successor. Return only an owned candidate to the
  verified compatible accepted version, preserving current data. A snapshot
  restore is not code rollback. Schema changes need compatible readers/writers
  or an explicitly qualified forward repair, never destructive undo.
- Check the next phase and the full remaining qualified path, including complete
  recovery, cleanup and justified contingency, before mutation. Derive enclosing
  deadlines from that path. If insufficient, leave the accepted version and keep
  preparation. Unknown results retain custody; only a known pre-dispatch failure
  may release its own reservation.

## Authority and historical exceptions

- No implicit grant, MFA answer, acceptance, expiry extension, ceiling increase,
  secret export, identity merge, data deletion or foreign lock cleanup. Preserve
  every ledger and unknown result. Existing Vercel credentials are separate from
  private host maintenance; do not relabel historical debit.
- Eight-hour account windows, two-hour human sign-in allowances, separately
  admitted retries and one-hour contingencies belonged to specific account
  rollout plans/grants. Preserve those operations' original obligations. Do not
  inherit these durations as defaults for any new publication, including other
  coordinated changes. New operations use their complete qualified measured path
  and specific owner authority, without amending old grants or ceilings.
- Changed authentication/provider/identity contracts still require genuine
  affected acceptance. Finite account experiments contain their compatible exit
  before expiry. Silence is not acceptance; extra budget never permits replaying
  an uncertain action.

Historical packets under outputs/, exports/ and external operation directories
are evidence for their original operations, not instructions for new ones. Use
successor plans. Do not edit sealed packets or inherit their old dates, censuses
and windows as new requirements.
